# BackIntel v0.0.1 release qualification

This package prepares the experimental analytical foundation for a release decision.
It is not a published release or a production-service acceptance record. Linear owns
execution status in INT-429 and INT-451; the dated result reports own measured evidence.

## Capability and architecture

The `ask` entry point runs one LangChain Deep Agents analyst with bounded, read-only
schema/query tools and offline SmolVM Python. It returns structured results, method,
caveats and executable evidence. The `analyze` entry point independently runs one
specialist with a bounded shell/Python workspace and exports report/chart/workbook
bundles through a clean renderer VM. Automatic delegation and runtime sub-agents are off.

The native benchmark routes are `openai/gpt-6-luna` for analysis and
`anthropic/claude-haiku-5-5` for advisory method assessment. The separate artifact
specialist defaults to `chatgpt-plan/gpt-6.1-sol`, medium reasoning. Native API credentials
and the specialist's private ChatGPT account connection are different authentication paths.
See the [README capability matrix](../README.md#capabilities-today),
[runtime boundaries](sandbox-environment.md), [native configuration](native-provider-credits.md)
and [specialist configuration](specialist-default.md).

This milestone establishes bounded descriptive business analysis. Production ETL,
forecasting/causal validity, unfamiliar-domain transfer, real 10 GiB acceptance, hosted
artifact delivery and continuous scheduling require their own roadmap acceptance.
Historical connector tests do not qualify every database deployment.

## Reproducible installation and review

Use Python 3.12 and `uv sync --frozen` from a clean source checkout, then run the README's
offline checks. Standard tests require neither model credentials nor private datasets.
SmolVM execution is qualified on macOS ARM64; its pinned binary/image preparation and
network/resource checks are documented separately. Live inference requires its own
configured credential path and allowance.

The dependency order is native provider/accounting PR10, evaluator PR8, then the campaign
and release evidence in PR9. Review findings, required hosted CI and clean-checkout
verification must be attached to the exact publication head before merge readiness.
The release decision must identify the final integration commit, its result reports,
supported capability matrix and remaining limitations. No merge, tag or deployment is
implied by preparing this document.

## Release and rollback handoff

Publish a tag/release only after the owner approves the concrete reviewed candidate.
Retain the previous main commit `51846a48e52e203eabefd7354182a1bd49ba72b6` as the
pre-adoption source identity. Existing users can continue a pinned checkout; adoption
must use the same pinned dependencies and documented runtime. Do not rewrite historical
experiments or rotate credentials during a source rollback. No hosted service or
customer migration is part of this release.
